# Evaluation evidence

This matrix maps the Celebration & Event Planner criteria to current implementation and executable evidence. Measured command results and verification limits are in [verification](verification.md); architecture and trust boundaries are in [architecture](architecture.md). The matrix does not assign or guarantee an external score.

| Criterion             | Implementation                                                                                                                                                                                                 | Executable evidence                                                                                                                                          |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Code quality**      | Strict TypeScript; focused UI, domain, AI, storage, and schema modules; type-aware promise/import checks; function complexity at most 15; maintained product and engineering guides                            | `format:check`, `lint`, `typecheck`, production build; focused domain and service tests                                                                      |
| **Efficiency**        | Genuine async structured streaming; one bounded pre-preview retry; cancellation; local versioned caches; deterministic arithmetic and bounded graph traversal; static pages and lazy feature loading           | Provider/handler progressive-delivery tests; cache/TTL/ownership tests; production browser JavaScript growth gate; `size:check` below 9 MB                   |
| **Security**          | Server-only credentials; ignored local environment; bounded strict requests; separate instructions/user data; no model tools; validated text output; CSP/HSTS; minimized follow-up context; metadata-only logs | Schema/prompt/provider/adversarial tests; origin/body/timeout regressions; browser CSP and hostile-text checks; `security:check`, `security:bundle`, `audit` |
| **Testing**           | Vitest, React Testing Library, fake-indexeddb, mocked LLM boundaries, production Playwright, axe-core, and four enforced coverage thresholds                                                                   | 562 automated tests and 33 Chromium cases in the recorded baseline; clean-runner GitHub Actions; all core coverage measures above 96%                        |
| **Accessibility**     | Semantic landmarks/headings; labelled controls; associated field errors; focus management; keyboard schedule moves; native dialogs; pending-save status; reduced motion; textual alternatives to charts        | Component validation/dialog tests; browser keyboard/mobile/focus cases; axe scans of primary pages and expanded error states                                 |
| **Problem alignment** | Event-specific weddings, birthdays, and community plans; budget allocation, vendor decisions, readiness, contingency workflows, schedules, ideas, reviewed tasks, and invitation drafts                        | Event-template/domain tests and full journeys for all three event types; explicit distinction between deterministic facts, user records, and AI suggestions  |

## Important evidence boundaries

- AI schema validation and prompt safeguards constrain behavior but do not establish perfect model truthfulness or injection resistance.
- Browser storage is local persistence, not an encrypted cloud vault or cross-device backup.
- Supplier categories and qualitative suggestions are not verified businesses, market prices, or availability guarantees.
- Origin checks do not authenticate non-browser callers. Deployment-wide per-IP throttling requires hosting configuration; see [deployment](deployment.md).
- Automated accessibility checks do not replace a complete assistive-technology review.
- Live provider, TLS, rate-limit enforcement, and real production load are separate from mocked local/CI tests.
