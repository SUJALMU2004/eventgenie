## Security and architecture assessment

- Strict bounded request schemas, supported event types/currencies, actual 16 KiB body reading, same-origin browser checks and safe typed errors apply to all three POST routes. Origin checks are CSRF friction, **not authentication or bot protection**.
- Server-only direct Gemini adapter uses configurable model selection, `streamText`, `Output.object`, `partialOutputStream`, full validation, no tools, bounded output tokens, 90-second generation timeout and at most one transient pre-preview retry. Provider retries are disabled. Total upload + generation remains below the configured 120-second function allowance.
- Application code owns financial arithmetic, stable IDs, completion defaults, task/date validation and transactional mutations. Adversarial tests include English, Hindi, Chinese, encoded instructions, HTML, invented IDs, negative financial overrides and unauthorized completion/deletion attempts. These demonstrate application boundaries with mocks; they do not prove a model can never produce misleading prose.
- React text rendering remains authoritative; no dangerous HTML execution path was added. Browser tests render hostile generated markup as literal text and check for injected elements/page exceptions. Local import prototype checks, size limits, ownership checks and escaped all-day calendar export remain covered.
- IndexedDB version 3, all older envelopes/migrations and owned atomic history are retained. New code does not delete saved browser data. All-day calendars, protected commitments and linked payment accounting remain deterministic.
- CSP/frame/referrer/permissions/nosniff headers are tested on real production responses. CSP permits inline scripts/styles for the present static Next rendering strategy; it excludes production `unsafe-eval`, third-party scripts and objects. This is defense in depth, not a nonce-based strict CSP claim.
- No credentials, guest records or event text are logged. The historical scan found no indicators in available history; baseline history contained zero commits, so it cannot establish anything about copies outside this repository.

## Live provider and performance

Exactly **one** controlled Phase 4 live request used the configured server-side key and generic synthetic birthday invitation context (**221 UTF-8 bytes**, no event title/date/venue/contacts). Actual `POST /api/plans/intelligence` returned **HTTP 200**, one incremental preview at **1,945 ms**, and a fully validated invitation result at **1,992 ms**. The provider log recorded **237 input / 44 output tokens**. No generated text or credential was printed. This verifies that operation/request only, not every live operation/event type or free-tier entitlement.

Local production `GET /plan`: first **127.3 ms**; warm samples **12.0, 10.9, 10.4, 10.6, 7.9 ms**, median **10.6 ms**. The initial HTML referenced 12 JS files: **796,334 raw bytes / 246,681 separately gzip-compressed bytes**. No throttling; these are local response/source-size measurements, not browser hydration cost, production p95 or a directly controlled Phase 3 benchmark comparison.

The maintained handler test measures delayed mock previews before final output using explicit 20/40ms fixture delays. A verbose local sample observed **51 ms** to preview and **102 ms** to complete; these are fixture timings, not provider performance. No UI timer simulates generation progress. The final JSON browser report records **585 ms cache miss / 235 ms cache hit**, with one request overall and an explicit **200 ms mock server delay**. Click-to-saved-confirmation measured **338 ms**. Reproduce through `npm run test:e2e`; the ignored `artifacts/playwright-results.json` retains those attachments. Cache repeat makes one request overall; exact financial questions make zero AI calls. Optional advanced components stay lazily loaded. Financial/template arrays, graphs, snapshots, conversations and caches remain bounded.
